# Fraud Detection Dashboard – 2022 FinTech Enterprise  

**Project ID:** p09 **Duration:** 8 weeks **Role:** ML Engineer (Priya Raman)  

---  

## Overview  
- **Problem:** Rising transaction fraud eroded customer trust; legacy rule‑based system produced high false‑positive rates.  
- **Solution:** Built an XGBoost‑based classifier with end‑to‑end MLOps pipelines (MLflow, Airflow, Docker, SageMaker).  
- **Outcome:** False‑positive rate ↓ 4.3 % → 1.7 % (≈ 60 % reduction); fraudulent volume detected ↑ 22 %.  

---  

## Engineering Log (chronological)  

### Week 1 – Project kickoff & data audit  
- 📂 Ingested 12 M transaction rows (Jan 2020 – Dec 2021) from AWS Redshift; 0.9 % labeled fraud.  
- ✅ Data quality check: 0.3 % missing values, 0.1 % duplicate rows → deduplication script (pandas 1.5).  
- 📊 Baseline: Logistic regression AUC 0.71, FPR 4.3 % (threshold 0.5).  

### Week 2 – Feature engineering prototype  
- 🛠️ Engineered 57 features: temporal (hour‑of‑day, day‑of‑week), amount buckets, device fingerprint entropy, velocity counts (1 min/5 min/1 h windows).  
- 🔧 Implemented categorical encoding with `category_encoders` (target encoding for merchant ID).  
- 📈 Early XGBoost (max_depth=6, n_estimators=200) yielded AUC 0.84 on 20 % hold‑out.  

### Week 3 – Pipeline formalization (MLflow)  
- 🗂️ Created `src/etl/` module; added `mlflow.start_run()` wrappers for each feature set version.  
- 📌 Logged: parameters, feature importances, ROC curves as artifacts.  
- 🧪 Ran 12 experiments (learning_rate ∈ {0.01,0.05,0.1}; max_depth ∈ {4,6,8}); best config: lr 0.05, depth 6, subsample 0.8.  

### Week 4 – Model scaling & SageMaker deployment  
- 🚀 Packaged model as a Docker image (python:3.9‑slim, XGBoost 1.7.2, mlflow‑sagemaker).  
- 📦 Pushed to ECR (repo: `fintech-fraud-dashboard/model`).  
- 🛠️ Deployed to SageMaker endpoint `fraud-detector-prod` (instance type `ml.m5.xlarge`).  
- ⏱️ Latency: 28 ms per request (well under 100 ms SLA).  

### Week 5 – CI/CD & Airflow orchestration  
- 📁 Added `Dockerfile` and `docker-compose.yml` for local dev; integrated with GitHub Actions (lint, unit tests, build).  
- 🗓️ Airflow DAG `retrain_fraud_model` (schedule: `@daily` 02:00 UTC). Steps:  
  1. Pull latest raw data from S3 bucket `s3://fintech-raw/transactions/`.  
  2. Run ETL script → feature store `s3://fintech-feature-store/`.  
  3. Train XGBoost with hyper‑params from MLflow registry (latest “Production” tag).  
  4. Register new model version, trigger SageMaker endpoint update via Boto3.  
- ✅ Added alert on Airflow task failure → Slack channel `#mlops-alerts`.  

### Week 6 – Monitoring & drift detection  
- 📊 Integrated SageMaker Model Monitor: data capture 100 % of inference payloads.  
- 🧪 Set up drift thresholds (KS‑statistic > 0.2) on key features (transaction amount, device entropy).  
- 📈 Dashboard (Grafana) shows nightly FPR trend; alert when FPR > 2.0 %.  

### Week 7 – A/B testing & rollout  
- 🎯 Deployed “shadow” model (new version) alongside production; routed 10 % of traffic via feature flag.  
- 📈 Shadow model reduced false positives by 0.6 % vs. baseline; no increase in latency.  
- ✅ Promoted shadow to production on 2022‑09‑14 after stakeholder sign‑off.  

### Week 8 – Documentation & handover  
- 📚 Wrote comprehensive README (`README.md`), API spec (OpenAPI 3.0), and runbooks for:  
  - Model retraining (Airflow).  
  - Endpoint scaling (auto‑scale policy based on 75 % CPU).  
  - Incident response (MLflow rollback steps).  
- 📦 Tagged repository `fintech-fraud-dashboard` v1.0.0; archived all experiment artifacts in S3 `s3://fintech-mlflow-artifacts/2022/`.

## Trade‑offs & Lessons Learned  

- **Feature store vs. on‑the‑fly engineering:** Persisting engineered features in S3 cut nightly ETL time by 40 % but added storage cost (~$120 / month).  
- **XGBoost depth:** Deeper trees (depth 8) improved AUC 0.86 → 0.01 gain, but increased inference latency to 55 ms, breaching SLA; kept depth 6.  
- **Model drift detection:** Early drift alerts prevented a potential 0.8 % FPR rise during a holiday sales spike.
