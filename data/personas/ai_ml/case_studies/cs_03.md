# Real‑Estate Document Analyzer – Phase 1 (2022, Real Estate)

- **Project ID:** p03  
- **Duration:** 6 weeks (Jan 10 – Feb 20 2022)  
- **Role:** NLP Specialist (Priya Raman)  

## Sprint 1 – Requirements & Data Prep (Week 1)  
- ✅ Received 3,214 lease PDFs from client’s legal team (average 12 pages each).  
- 📂 Converted PDFs → text using `pdfminer.six` v20211012; OCR fallback with Tesseract 4.1 for 8 % scanned pages.  
- 🗂️ Built PostgreSQL 13 schema: `leases(id PK, raw_text TEXT, extracted JSONB)`.  
- 📊 Initial manual annotation: 500 clauses labeled by senior paralegals (date, rent, termination).  
- 🏷️ Inter‑annotator agreement κ = 0.87 → high consistency.  

## Sprint 2 – Baseline Model (Week 2)  
- 🧪 Trained spaCy 3.5 NER on 500 annotated samples (80/20 train/val split).  
- 🏋️‍♀️ Training config: `batch_size=32`, `dropout=0.2`, `max_epochs=30`.  
- 📈 Validation F1: 0.78 (date), 0.74 (rent), 0.71 (termination).  
- 🐳 Dockerfile created (Python 3.9, spaCy, psycopg2) – image size 210 MB, pushed to internal registry `registry.company.com/realestate-analyzer:0.1`.  

## Sprint 3 – Data Augmentation & Hyper‑tuning (Week 3)  
- 🔄 Applied synonym replacement & date format variation (e.g., “01/01/2023”, “Jan 1, 2023”).  
- 🎛️ Grid‑search over `learning_rate` (1e‑4–5e‑4) and `dropout` (0.1–0.3).  
- 📈 Best config: `lr=3e‑4`, `dropout=0.15` → validation F1 ↑ to 0.84 (date), 0.81 (rent), 0.79 (termination).  
- 🧹 Cleaned 2,718 false‑positive patterns (e.g., “rent” in header).  

## Sprint 4 – Production Pipeline (Week 4)  
- 🛠️ Built async inference service (`FastAPI` v0.78) exposing `/extract` endpoint.  
- 📦 Containerized with Docker‑Compose (app + PostgreSQL).  
- ⏱️ Latency: avg 0.42 s per document (single‑core CPU, 2 vCPU, 4 GB RAM).  
- 📊 Integrated with client’s document ingestion queue (RabbitMQ).  

## Sprint 5 – Evaluation & User Acceptance (Week 5)  
- 📊 Ran batch on 2,714 historic leases (held‑out set).  
- ⏱️ Manual extraction time: 12 min → automated 2 min per doc (≈ 86 % time reduction).  
- 🎯 Extraction accuracy (entity‑level F1) = **92 %** overall (date 93 %, rent 91 %, termination 92 %).  
- 🗣️ Feedback loop: legal team flagged 27 edge‑case clauses; added to training set for next iteration.  

## Sprint 6 – Handoff & Documentation (Week 6)  
- 📚 Delivered run‑books: Docker deployment, DB backup schedule, model versioning (v1.0).  
- 🗂️ Exported model to `model/spacy_ner_v1` (size 45 MB) with `spacy package`.  
- 🎓 Conducted 2‑hour knowledge transfer for client’s MLOps engineers (Docker, PostgreSQL, FastAPI).  

## Key Metrics & Trade‑offs  
| Metric | Value | Comment |
|--------|-------|---------|
| Manual time per doc | 12 min → 2 min | 86 % reduction, still requires human QA for rare clauses |
| Extraction accuracy (F1) | 92 % | Meets SLA >90 %; further gains would need larger annotated corpus |
| Inference latency | 0.42 s | Acceptable for batch; real‑time UI would need GPU or model quantization |
| Docker image size | 210 MB | Small enough for on‑prem deployment behind firewall |
| PostgreSQL storage growth | +0.8 GB for 3 k docs | JSONB indexing on `entity_type` keeps query time <10 ms |
