# Clinical Notes Summarizer (2020 – Healthcare)

## Context
In early 2020 a large hospital network (enterprise‑level client) approached us with a painful bottleneck: physicians were spending **up to 30 minutes per patient** scrolling through dense electronic health record (EHR) notes. The organization wanted a solution that could automatically generate concise, clinically accurate abstracts of each encounter, freeing up clinicians to focus on decision‑making rather than paperwork. The project timeline was tight—**10 weeks**—and the deliverable needed to integrate seamlessly with the existing AWS‑based infrastructure.

## Challenge
- **Domain‑specific language:** Medical jargon, abbreviations, and varying note structures made off‑the‑shelf summarizers unreliable.  
- **Regulatory constraints:** HIPAA compliance required that all data processing stay within the client’s VPC and that model artifacts be version‑controlled.  
- **Performance expectations:** Summaries had to be generated in under **2 seconds** per note while maintaining high linguistic fidelity (target ROUGE‑L ≥ 0.70).  
- **Operational stability:** The solution needed a robust CI/CD pipeline and clear model‑version tracking to support continuous improvement without disrupting clinical workflows.

## Approach
1. **Data preparation:** Extracted 1.2 M de‑identified clinical notes from the client’s data lake, applied custom tokenization to preserve medical entities, and split the corpus into 800 k training, 200 k validation, and 200 k test examples.  
2. **Model selection & fine‑tuning:** Chose **BART‑large** from Hugging Face Transformers as the base architecture due to its strong abstractive capabilities. Fine‑tuned for 3 epochs on 8 × p3.2xlarge GPU instances, employing mixed‑precision training to reduce memory pressure.  
3. **Evaluation loop:** Implemented a validation script that computed ROUGE‑L, BLEU, and a domain‑specific factuality metric (based on MedSpaCy entity matching). Early stopping was triggered at ROUGE‑L = 0.71 on the held‑out set.  
4. **Service layer:** Wrapped the model in a **FastAPI** microservice, exposing a `/summarize` endpoint that accepted raw note text and returned a JSON payload with the abstract and confidence scores.  
5. **MLOps pipeline:**  
   - **Docker** containerization for reproducibility.  
   - **AWS SageMaker** for scalable inference (multi‑model endpoint).  
   - **MLflow** for experiment tracking, model registry, and versioned deployment.  
   - **GitHub Actions** drove CI (linting, unit tests) and CD (automatic SageMaker model update on merge to `main`).  
6. **Security:** All traffic encrypted via TLS; IAM roles limited to least‑privilege access; logs stored in encrypted CloudWatch groups.

## Stack
- **Languages & Frameworks:** Python 3.9, PyTorch, Hugging Face Transformers, FastAPI  
- **Container & Orchestration:** Docker, AWS SageMaker multi‑model endpoints  
- **MLOps Tools:** MLflow (tracking & registry), GitHub Actions (CI/CD)  
- **Infrastructure:** AWS (S3 for data, IAM, VPC, CloudWatch)  
- **Evaluation:** ROUGE‑L, BLEU, MedSpaCy entity‑level factuality  

## Results
| Metric | Before | After | Improvement |
|--------|--------|-------|-------------|
| Avg. physician reading time per note | 30 min | 11 min | **62 % reduction** |
| Summarization quality (ROUGE‑L) | N/A (manual) | **0.71** | Meets target |
| Inference latency (99th percentile) | N/A | **1.8 s** | Within SLA |
| Deployment frequency | Quarterly releases | **Bi‑weekly** via CI/CD | Faster iteration |

The summarizer was rolled out to 12 pilot departments in Q4 2020, receiving positive feedback (average user satisfaction score = 4.6/5). The model registry now holds three successive versions, each tracked in MLflow with clear performance deltas.

## What I Would Do Differently
- **Data augmentation:** Incorporate synthetic clinical note generation (e.g., using GPT‑4) to expand rare pathology cases, which could improve factual coverage.  
- **Hybrid architecture:** Combine extractive pre‑processing (e.g., using a lightweight BERT‑based sentence selector) with the abstractive BART model to reduce inference cost further, potentially bringing latency below 1 s.  
- **Explainability layer:** Integrate attention‑visualization dashboards for clinicians to verify why certain sentences were emphasized, enhancing trust and aiding regulatory audits.  
- **Long‑term monitoring:** Set up automated drift detection on input note distributions and downstream clinical outcomes to trigger retraining alerts earlier.  

Overall, the project demonstrated how a focused NLP pipeline, built with modern transformer models and disciplined MLOps practices, can deliver tangible efficiency gains in a high‑stakes healthcare environment.
