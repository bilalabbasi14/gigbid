# Dynamic Pricing Engine – 2023 | Hospitality Startup  

**Project ID:** p12 **Role:** ML Engineer (Priya Raman) **Duration:** 7 weeks  

---  

- **Week 1 – Data Ingestion & Exploration**  
  - Imported 3.2 M hotel booking records (2018‑2022) from S3 into a Pandas DataFrame.  
  - Performed feature engineering: created `lead_time_days`, `seasonality_index` (sin/cos of day‑of‑year), and one‑hot encoded `room_type`.  
  - Identified missing values in `cancellation_policy` (2.4 %) → imputed with mode.  
  - Commit: `feat: initial data pipeline, add feature engineering utils`  

- **Week 2 – Baseline Modeling**  
  - Split data: 70 % train / 15 % validation / 15 % test (time‑based split to avoid leakage).  
  - Trained `LinearRegression` → R² = 0.42, MAE = $12.3.  
  - Logged baseline metrics to MLflow (run #b1c9e7).  
  - Commit: `chore: add baseline model and MLflow tracking`  

- **Week 3 – Model Selection & Hyper‑tuning**  
  - Evaluated `RandomForestRegressor`, `XGBRegressor`, and `GradientBoostingRegressor`.  
  - GradientBoostingRegressor (n_estimators=350, learning_rate=0.05, max_depth=6) achieved best validation R² = 0.68, MAE = $8.7.  
  - Used `scikit-learn` GridSearchCV with 5‑fold CV (parallelized via `joblib`).  
  - Commit: `perf: switch to GradientBoostingRegressor, add hyper‑parameter grid`  

- **Week 4 – Model Serialization & Containerization**  
  - Serialized model with `joblib.dump` (size = 4.2 MB).  
  - Created Dockerfile: `FROM python:3.10‑slim`, installed `scikit-learn`, `mlflow`, `boto3`.  
  - Built image `pricing-engine:2023.04` (≈ 210 MB).  
  - Commit: `build: Dockerfile for SageMaker endpoint, add model artifact`  

- **Week 5 – Deployment to AWS SageMaker**  
  - Pushed Docker image to ECR (repo: `123456789012.dkr.ecr.us-east-1.amazonaws.com/pricing-engine`).  
  - Created SageMaker endpoint `pricing-endpoint-prod` with `ml.m5.large` instance (2 vCPU, 8 GB RAM).  
  - Configured auto‑scaling target latency < 5 s; actual median latency measured at 3.8 s under 150 RPS.  
  - Commit: `ci/cd: Terraform script for SageMaker endpoint, enable auto‑scaling`  

- **Week 6 – MLOps & Monitoring**  
  - Integrated MLflow Model Registry: versioned model `v1.0.0`.  
  - Set up CloudWatch alarms for prediction latency > 5 s and error rate > 0.2 %.  
  - Implemented drift detection using `sklearn` `KSStatistic` on `lead_time_days`; triggered weekly retraining flag when p‑value < 0.01.  
  - Commit: `ops: MLflow registry hooks, CloudWatch alarms, drift detection script`  

- **Week 7 – A/B Testing & Business Impact**  
  - Ran 4‑week A/B test: 30 % of rooms served by dynamic pricing, 70 % control.  
  - Result: **Revenue per Available Room (RevPAR) ↑ 9 %** (p < 0.01).  
  - Pricing adjustment latency consistently **< 5 seconds** across peak loads.  
  - Delivered hand‑off documentation (API spec, model versioning policy, rollback procedure).  
  - Commit: `docs: final runbook, API Swagger spec, rollback playbook`  

---  

**Key Takeaways**  
- GradientBoostingRegressor provided the best bias‑variance trade‑off for sparse, seasonal booking data.  
- Containerizing the inference stack enabled rapid SageMaker deployment and straightforward scaling.  
- MLflow + CloudWatch formed a lightweight yet effective MLOps loop, keeping latency under the 5‑second SLA and surfacing data drift early.  

*All work completed within the 7‑week sprint, meeting the client’s real‑time pricing requirement and delivering measurable revenue uplift.*
