# Media Content Tagger (2020, Media Industry)

When the media enterprise approached us in early 2020, their editorial pipeline was choking on the sheer volume of visual assets. Every new article or video required a set of descriptive tags—genre, location, featured objects—to make the content searchable and to feed recommendation engines. The existing manual process was a bottleneck: analysts were spending hours sifting through millions of images, and the lag was causing publishing delays and missed ad revenue. I was brought on as the Computer Vision Engineer to design an end‑to‑end tagging system that could keep pace with their daily ingest rate.

My first step was to audit the taxonomy the client used for tagging. They had a hierarchical schema with about 150 leaf categories ranging from “sports‑action” to “urban‑nightscape.” To train a model that respected this taxonomy, I curated a labeled dataset of 120,000 images sourced from their archives, ensuring each class had at least 500 examples. I split the data 80/10/10 for training, validation, and testing, and applied standard OpenCV augmentations—random crops, brightness jitter, and Gaussian blur—to improve robustness against the varied lighting conditions typical of user‑generated content.

For the backbone I selected ResNet‑50, a proven architecture in image classification that balances accuracy and inference speed. Using PyTorch 1.7, I fine‑tuned the network on the custom taxonomy, employing a cross‑entropy loss with class‑weighting to mitigate the long‑tail distribution. After 12 epochs on an AWS p3.2xlarge instance, the model reached 89 % top‑1 accuracy on the held‑out test set, comfortably meeting the client’s target of 85 %.

Deployment was the next challenge. The client ran their production workloads on AWS, so I containerized the preprocessing pipeline and the model inference code with Docker, exposing a lightweight REST API. I chose Amazon SageMaker because it offered managed scaling and A/B testing capabilities. The Docker image was pushed to ECR, and a SageMaker endpoint was created with an initial instance type of ml.m5.large, auto‑scaling up to ml.c5.2xlarge during peak ingest periods.

Integrating the endpoint into the existing CMS required minimal changes. The CMS now streams each new image through an OpenCV preprocessing step—resizing to 224 × 224, normalizing pixel values—and then calls the SageMaker endpoint for a tag prediction. The response includes the top three categories with confidence scores, which the CMS stores alongside the asset metadata.

The impact was immediate. Tagging throughput jumped from roughly 3,000 images per hour to over 36,000 images per hour—a twelve‑fold increase—allowing the editorial team to publish content within minutes of ingestion. The 89 % accuracy meant that only 11 % of tags required manual review, cutting the manual workload by roughly 85 %. We also set up CloudWatch dashboards to monitor latency (average 150 ms per request) and error rates, ensuring the system stayed reliable as the image volume grew.

Looking back, the key trade‑off was balancing model size against latency. A larger EfficientNet‑B4 would have nudged accuracy higher, but the added inference time would have jeopardized the real‑time publishing goals. By sticking with ResNet‑50 and optimizing the Docker image for CPU inference, we hit the sweet spot between speed and performance, delivering a solution that scaled with the client’s expanding media library.
