# Automated Grading Assistant — 2021, Education Agency  

**Project ID:** p06 | **Duration:** 7 weeks | **Role:** Data Scientist (AI/ML Engineer)  

---  

### Overview  
- **Problem:** Instructors manually graded ~1,200 short‑answer responses per week, averaging 45 min per batch.  
- **Goal:** Reduce human grading time while preserving scoring fidelity.  
- **Solution Stack:** Python 3.9, scikit‑learn 0.24, XGBoost 1.4, FastAPI 0.78, Docker 20.10.  

---

### Technical Trade‑offs  

- **TF‑IDF vs Embeddings:** Chose TF‑IDF for deterministic feature space and negligible GPU cost; acceptable because short answers lack deep semantic variance.  
- **XGBoost vs Deep Nets:** XGBoost gave higher correlation with far fewer parameters, simplifying model explainability for instructors.  
- **Batch FastAPI vs Streaming:** Batch endpoint minimized request overhead; streaming would increase complexity for marginal latency gain.  

---  

### Post‑Launch Reflections  

- **Scalability:** Current setup handles up to 2,000 answers/hour; future work includes horizontal autoscaling and model distillation to <50 ms per batch.  
- **Maintainability:** All hyper‑parameters stored in `config.yaml`; model artifacts versioned with DVC (v2).  
- **Ethical Guardrails:** Added a “confidence threshold” (0.65) to flag low‑certainty scores for manual review, reducing potential bias.  

---  

**Result:** Delivered a production‑ready automated grading assistant within a 7‑week sprint, exceeding the client’s KPI of ≥70 % time reduction and achieving a strong 0.88 correlation with expert graders.
