# Volunteer Matchmaking Platform (2021) – Non‑Profit Agency  

## Context  
In early 2021 a mid‑size non‑profit agency was expanding its volunteer programs across multiple cities. Their existing spreadsheet‑based system could only match volunteers to projects using keyword filters, which led to many mismatches. The agency needed a smarter way to surface volunteers whose skill descriptions aligned semantically with project requirements, while keeping the solution lightweight enough to deploy on their modest on‑premise servers.

## Challenge  
- **Unstructured skill data**: Volunteers described their abilities in free‑form text (e.g., “experience with community outreach and event planning”).  
- **Scalability**: The platform had to handle ~12 k volunteer profiles and ~1.5 k active project postings, with new entries added weekly.  
- **Speed**: Matching queries needed to return results within 300 ms to keep the UI responsive.  
- **Limited resources**: The agency’s IT budget allowed only open‑source tools and containerised deployment.

## Approach  
I led the NLP engineering effort, designing an end‑to‑end pipeline that transformed raw text into dense vector embeddings and performed semantic similarity search. The workflow comprised:

1. **Data preprocessing** – Normalised text (lower‑casing, punctuation removal) and applied spaCy’s `en_core_web_md` model for tokenisation and lemmatisation.  
2. **Embedding generation** – Leveraged spaCy’s built‑in word‑vectors (300‑dimensional) and fine‑tuned a lightweight sentence‑transformer (DistilBERT‑base) on a curated dataset of 3 k manually labelled volunteer–project pairs to improve domain relevance.  
3. **Vector store** – Persisted all embeddings in a PostgreSQL database with the `pgvector` extension, enabling efficient approximate nearest‑neighbor (ANN) queries via `inner_product` similarity.  
4. **API layer** – Exposed a FastAPI endpoint (`/match`) that accepted a project description, computed its embedding on‑the‑fly, and returned the top 10 volunteers sorted by relevance score.  
5. **Containerisation** – Packaged the service, spaCy model, and the fine‑tuned transformer into a Docker image, orchestrated with Docker‑Compose for easy staging and production rollout.

## Results  
- **Match relevance** increased by **34 %** measured via A/B testing against the previous keyword filter (average relevance score rose from 0.62 to 0.83).  
- **Volunteer signup rate** grew by **18 %** within two months of launch, as volunteers received more pertinent project suggestions.  
- **Latency** met the target: 95 % of requests returned under **250 ms** (average 187 ms).  
- The Dockerised service required only **0.8 CPU** and **512 MiB RAM** on a single VM, staying well within the agency’s budget.

## What I Would Do Differently  
1. **Hybrid Retrieval** – Incorporate a sparse lexical index (e.g., BM25 via Elasticsearch) alongside the dense vector search to capture exact keyword matches for niche skills, improving recall for rare terms.  
2. **Dynamic Model Updating** – Set up an active‑learning loop where newly accepted matches feed back into the fine‑tuning dataset, allowing the transformer to evolve with emerging volunteer terminology.  
3. **Edge Caching** – Deploy a small Redis cache for the most frequent project embeddings to shave another ~30 ms off peak latency.  
4. **Explainability** – Add a simple attention‑heatmap overlay in the UI to show volunteers why a particular match was suggested, boosting trust and transparency.  

Overall, the project delivered a measurable uplift in volunteer engagement while remaining fully open‑source and cost‑effective, demonstrating how targeted NLP and semantic search can transform matchmaking in the non‑profit sector.
