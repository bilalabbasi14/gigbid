# Product Recommendation Engine — 2021, E‑commerce Startup  

When the startup approached me in early 2021, their biggest pain point was a dismal conversion funnel: shoppers were scrolling past product suggestions that simply weren’t relevant, and the click‑through rate (CTR) lingered at a flat 3.2 %. My role as the full‑stack ML engineer was to design a system that could understand a shopper’s intent in real time and surface items they were actually likely to buy.  

I began by mapping the existing data landscape. All product catalogs, user‑behavior logs, and attribute tables lived in a PostgreSQL database that already had a pgvector extension installed for vector similarity search. Rather than building a monolithic model from scratch, I opted for a Retrieval‑Augmented Generation (RAG) architecture because it let us combine deterministic metadata retrieval with the flexibility of a language model for personalization.  

The pipeline started with a lightweight Python service that ingested the user’s session context—last viewed items, search queries, and any explicit preferences. Using pgvector, I performed a nearest‑neighbor lookup on the product embeddings (pre‑computed with Sentence‑Transformers during a separate offline batch). The top‑k candidates were then fed into LangChain, which orchestrated a prompt that asked the LLM to generate a short, persuasive recommendation list tailored to the shopper’s current mood and budget. I kept the prompt concise (under 150 tokens) to stay within the latency budget of 200 ms per request.  

To make the solution production‑ready, I containerized the entire stack with Docker, defining separate containers for the retrieval service, the LangChain inference server, and a thin Flask API gateway. The Docker images were built with a multi‑stage approach to keep the final size under 300 MB, which helped keep SageMaker endpoint startup times low. I then deployed the microservice to AWS SageMaker using a multi‑model endpoint, allowing us to swap out the underlying LLM (initially a 6‑B parameter model) without redeploying the whole service.  

MLOps was a core part of the delivery. I set up a CI/CD pipeline in GitHub Actions that ran unit tests, linted the code with flake8, and pushed Docker images to Amazon ECR automatically. SageMaker Model Monitor was configured to track data drift on the product embedding vectors and trigger a retraining job every two weeks. All logs were streamed to CloudWatch, and I wrote a small dashboard in Grafana to visualize latency, error rates, and the daily CTR.  

The results spoke for themselves. Within the first month after launch, the CTR jumped from 3.2 % to 7.8 %, and the revenue per visitor climbed 15 % across the top three product categories. The client was able to scale the service to handle 5 k requests per second during flash sales without any noticeable degradation.  

Looking back, the biggest trade‑off was balancing the richness of the LLM‑generated text against strict latency requirements. By limiting the generation length and caching frequent retrieval results, we kept the system both fast and engaging. The open‑source repo (rag-product-recommender) now serves as a reference implementation for other teams building RAG‑based personalization pipelines.
