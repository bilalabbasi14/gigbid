# Compliance Document Generator — 2023, Legal Industry  

When the legal department of a large enterprise approached us in early 2023, they were drowning in repetitive contract drafting. Every new agreement required a junior associate to spend roughly four hours pulling clauses from a shared drive, copying them into a Word template, and then manually adjusting variables like dates, party names, and jurisdiction. The process was error‑prone and scaled poorly as the company’s transaction volume grew. I was brought on as the full‑stack engineer to design a self‑service tool that would let non‑technical staff generate fully formatted contracts in minutes.

My first step was to map out the data model. The existing contracts lived as static .docx files with placeholder tokens (e.g., `{{client_name}}`). I chose Django for the backend because its admin interface made it easy for the legal team to manage template versions without developer intervention. Using Django REST Framework, I exposed a clean JSON API that accepted a payload of user‑entered values and returned a generated document. The heavy lifting of merging data into the Word templates was handled by the `docxtpl` library, which lets you treat a .docx file as a Jinja2‑style template. This meant we could keep the familiar Word formatting while programmatically substituting fields.

On the data side, PostgreSQL was a natural fit for its robust support of JSONB columns, which we used to store the variable mappings for each contract type. The `psycopg2` driver gave us low‑latency connections, and I added indexes on the `template_id` and `created_at` columns to keep query times under 30 ms even as the monthly volume approached 1,200 documents.

The front‑end was built with React and TypeScript to give the legal staff a responsive, type‑safe experience. I created a dynamic form generator that reads the template schema from the API and renders the appropriate input fields—text boxes, date pickers, and dropdowns. For a live preview, I integrated `react-pdf` to render the resulting PDF in the browser as soon as the user hit “Generate”. This immediate feedback reduced the need for back‑and‑forth revisions.

Docker was used throughout the development pipeline. I containerized the Django app, the PostgreSQL database, and the React build process, then orchestrated them with Docker Compose for local testing. In production, the containers ran on an internal Kubernetes cluster, allowing us to scale the REST service horizontally during peak drafting periods without any downtime.

We delivered the MVP after 14 weeks of sprints, adhering to the client’s tight timeline. Post‑launch metrics were striking: the average contract drafting time fell from four hours to roughly fifteen minutes, and the system reliably processed over 1,200 documents per month with sub‑second response times for most API calls. The legal team praised the intuitive UI and the ability to audit every generated contract through the Django admin logs. The project not only solved a critical bottleneck but also laid a foundation for future automation of other legal documents.
