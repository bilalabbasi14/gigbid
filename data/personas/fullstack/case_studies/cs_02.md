# Real‑time Fleet Tracking Dashboard – 2021 (Logistics)

When the logistics firm approached us in early 2021, their dispatch center was drowning in static spreadsheets and delayed GPS pings. They needed a single pane of glass that could show every truck’s exact location, speed, and cargo status the moment a new telemetry packet arrived. I was brought on as the full‑stack engineer to design and deliver that capability within a tight 20‑week window.

The first step was to map out the data flow. The vehicles were already streaming JSON payloads to a RabbitMQ broker, but we needed sub‑second latency for the dispatchers. I introduced Redis as an in‑memory store for the latest position of each asset, using the `ioredis` client to handle high write throughput. Every incoming telemetry event triggered a lightweight Node.js service built on Express, which wrote the snapshot to Redis and also persisted a historical record in PostgreSQL via the `pg` library for later analytics.

To expose this data to the front end, I chose GraphQL because it let us request exactly the fields the dashboard needed without over‑fetching. I set up an Apollo Server on top of Express (`apollo-server-express`) and defined a subscription schema that pushed updates whenever Redis keys changed. The subscription mechanism used WebSocket transport, which kept the client connection open and delivered location updates in real time.

On the client side, I built a React application with TypeScript, using `apollo-client` to manage queries and subscriptions. The UI was a map component powered by Mapbox GL JS, overlaid with markers that refreshed instantly as the GraphQL subscription emitted new coordinates. I added a status panel that showed engine health, temperature, and driver notes, all pulled from the same GraphQL endpoint. To keep the bundle lean, I leveraged code‑splitting and lazy loading for heavy map assets.

Testing and delivery were automated from day one. I wrote unit tests with Jest for both the Node services and the React components, achieving around 85 % coverage. GitHub Actions pipelines ran the test suite on every push, built Docker images, and pushed them to our private registry. Docker Compose orchestrated the whole stack—Node, Redis, PostgreSQL, and the React dev server—so onboarding new developers took under an hour.

After the 20‑week sprint, the dashboard went live in June 2021. Dispatchers reported that they could now see a truck’s exact position within 1–2 seconds of movement, cutting response time by roughly 35 %. Over the following year the system logged 99.9 % uptime, with no major incidents despite handling peaks of 2,500 concurrent vehicle streams. The client praised the modular architecture, noting that adding new telemetry fields required only a schema tweak and a corresponding UI component.

Looking back, the combination of Redis for ultra‑fast state, GraphQL subscriptions for efficient data delivery, and a typed React front end gave the logistics firm the live visibility they needed while keeping the codebase maintainable and extensible for future features.
