# Internal Audit Workflow Tool (2022 – Legal)

**Project ID:** p15  
**Duration:** 8 weeks  
**Role:** Full‑stack Engineer (Daniel Okafor)  

---

## Overview
- Built a Kanban‑style audit task manager for a large legal enterprise.  
- Stack: React + TypeScript front‑end, Apollo Client/Server, Node.js + Express back‑end, GraphQL API, PostgreSQL DB, Dockerized deployment.  
- Primary goal: enable compliance teams to assign, track, and review audit tasks across multiple departments.

---

## Sprint 1 (Weeks 1‑2) – Foundations & Architecture  

- **Repo init**: `git init audit-workflow-tool`; created monorepo with `frontend/` and `backend/` directories.  
- **Docker**: Added `Dockerfile` for Node (v18) and `docker-compose.yml` with Postgres 13 container; CI pipeline (GitHub Actions) runs `docker compose up --build` on each PR.  
- **Schema design**:  
  - `tasks` table (id PK, title, description, status ENUM[TODO, IN_PROGRESS, DONE], assignee_id, department_id, created_at, updated_at).  
  - `audit_cycles` table to group tasks; foreign key to `tasks`.  
  - Index on `status` and `assignee_id` → query latency < 30 ms for dashboard loads.  
- **GraphQL**: Set up `apollo-server-express`; generated type‑defs from DB schema using `graphql-codegen`.  

---

## Sprint 2 (Weeks 3‑4) – Core UI & Drag‑Drop  

- **React scaffold**: Created Next.js app (`npx create-next-app@13 --typescript`).  
- **State management**: Integrated `apollo-client` with `InMemoryCache`; enabled optimistic UI updates for drag‑and‑drop actions.  
- **Kanban board**: Implemented with `react-beautiful-dnd`; columns map to `status` values.  
- **Performance**: Measured render time for 500 tasks → 120 ms average; added `React.memo` to column components, cut to 78 ms.  
- **Accessibility**: Added ARIA live region announcements for drag events; passed axe-core audit with 0 violations.  

---

## Sprint 3 (Weeks 5‑6) – Business Logic & Security  

- **Mutation flow**: `moveTask(taskId, newStatus)` → GraphQL mutation updates DB and returns updated task; optimistic response ensures UI reflects move instantly.  
- **Authorization**: Implemented JWT‑based middleware in Express; role‑based checks (`audit_manager`, `auditor`).  
- **Audit trail**: Added `task_history` table; every status change logs `user_id`, `prev_status`, `new_status`, timestamp.  
- **Testing**:  
  - Unit: 85 % coverage with Jest (frontend) and Mocha/Chai (backend).  
  - E2E: Cypress scripts covering task creation, drag‑drop, and permission enforcement; 12 min CI run time.  

---

## Sprint 4 (Weeks 7‑8) – Scaling, Deployment & Handoff  

- **Connection pooling**: Configured `pg-pool` with max 20 connections; sustained 150 concurrent API calls with < 200 ms latency.  
- **Horizontal scaling**: Added `replicas: 3` in Docker Swarm stack; load testing with k6 showed linear throughput increase.  
- **CI/CD**: Implemented semantic-release; auto‑generated changelog and Docker image tags (`v1.0.0` → `v1.2.3`).  
- **Documentation**: Produced Swagger‑like GraphQL docs via GraphQL Voyager; wrote README with setup steps, environment variable matrix, and runbooks.  

---

## Outcomes  

- **Audit cycle time**: Reduced from 12 days to 9.4 days (‑22 %).  
- **User satisfaction**: 4.5 / 5 average from post‑deployment survey (N = 48).  
- **Adoption**: 96 % of compliance staff migrated within 2 weeks; legacy spreadsheet usage dropped to < 5 %.  

---

## Reflections & Trade‑offs  

- Chose GraphQL over REST to minimize over‑fetching; resulted in a 30 % reduction in payload size for board refreshes.  
- `react-beautiful-dnd` gave smooth drag experience but added ~12 KB bundle size; mitigated with code‑splitting (`dynamic` import on the board component).  
- PostgreSQL handled relational integrity well, but future feature “real‑time notifications” may benefit from a pub/sub layer (e.g., Redis Streams).
