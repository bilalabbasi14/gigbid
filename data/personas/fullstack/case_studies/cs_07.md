# Reservation System for Boutique Hotels (2020 – Hospitality)

## Context
In early 2020 a boutique hotel startup with three properties in Lagos sought to replace its manual phone‑booking process with a modern, self‑service reservation platform. The goal was to let guests check availability, book rooms, and pay instantly, all while keeping operational overhead low. The team hired me as Lead Engineer to design and deliver the product within a tight 9‑week window.

## Challenge
- **Rapid time‑to‑market:** The startup needed a live booking engine before the high‑season rush in June 2020.  
- **Zero‑friction payments:** Previous attempts with legacy payment gateways suffered a 12 % failure rate, hurting guest confidence.  
- **Scalable data layer:** With only a handful of rooms now, the system still had to handle future expansion to ten or more locations.  
- **Low maintenance:** As a startup, the client could not afford a large DevOps team; the solution had to be largely serverless.

## Approach
1. **Product discovery & sprint planning** – Conducted three 2‑hour workshops with the founders to map user journeys, define the data model, and lock the MVP scope.  
2. **Serverless architecture** – Chose **Next.js** with **TypeScript** for the front‑end and API routes, deploying to Vercel for instant CDN edge caching.  
3. **Auth & DB** – Leveraged **Supabase** (PostgreSQL + auth) via the **supabase‑js** client, allowing us to skip custom auth scaffolding and get a fully managed DB in minutes.  
4. **Payments** – Integrated **Stripe Checkout** using the **stripe‑react** library, handling payment intent creation on the serverless API route and confirming the transaction client‑side.  
5. **UI/UX** – Built a responsive UI with **Tailwind CSS**, using utility‑first classes to iterate quickly and keep the CSS bundle under 30 KB.  
6. **Date handling** – Employed **date‑fns** for timezone‑aware availability calculations and formatting, avoiding Moment’s large footprint.  
7. **Testing & QA** – Wrote unit tests with **Jest** for the reservation logic and performed end‑to‑end flows on Cypress across Chrome, Firefox, and Safari.  

All code lived in a public GitHub repo (`github.com/yourusername/boutique-hotel-reservations`) with CI pipelines that ran lint, type‑check, and tests on every push.

## Results
- **Occupancy boost:** After launch, the average occupancy rose from **62 % to 78 %** within six months, driven by 24/7 online booking and instant confirmation.  
- **Payment reliability:** Stripe integration eliminated payment failures; the platform recorded **zero failed captures** during the first year.  
- **Development speed:** Delivered the MVP in **9 weeks** (exactly the planned timeline), with only 3 weeks of post‑launch bug‑fixing.  
- **Operational cost:** Serverless hosting kept monthly infrastructure spend under **$45**, well within the startup’s budget.  

## What I Would Do Differently
1. **Introduce a caching layer for availability** – While Supabase handled reads well, a Redis cache (via Vercel Edge Functions) would reduce latency for high‑traffic periods.  
2. **Modularize payment logic** – Abstract the Stripe integration into a reusable service to simplify future additions like Apple Pay or subscription‑based packages.  
3. **Add analytics early** – Embedding Segment or a lightweight GA4 implementation from day 1 would have provided faster insight into conversion funnels.  
4. **Implement feature flags** – Using LaunchDarkly or a simple config flag would allow A/B testing of UI tweaks without redeploying.  

Overall, the project demonstrated how a lean tech stack—Next.js, Supabase, and Stripe—can deliver a production‑grade reservation system for a hospitality startup on a shoestring schedule.
