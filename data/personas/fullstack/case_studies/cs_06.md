# Telehealth Video Consultation Platform – 2021 | Healthcare  

**Project ID:** p06 **Duration:** 16 weeks **Role:** Full‑stack Engineer (Daniel Okafor)  

---  

### Sprint 1 (Weeks 1‑2) – Foundations & Architecture  
- Set up monorepo with **Nx** workspace; shared TypeScript config for front‑end (React/Next.js) and back‑end (Node/Express).  
- Chose **PostgreSQL 13** on **Docker** (postgres:13‑alpine) for deterministic dev environments.  
- Defined API contract (OpenAPI 3.0) for appointment CRUD, token issuance, and audit logging.  
- Security baseline: enforced **TLS 1.3**, HTTP‑Only + Secure cookies, CSP header `default-src 'self'`.  

### Sprint 2 (Weeks 3‑4) – Core Backend & Token Service  
- Implemented `/api/session-token` endpoint using **jsonwebtoken** (HS256) with 15‑min expiry.  
- Integrated **twilio-video** SDK server‑side: generated Access Tokens with `VideoGrant`.  
- Added PostgreSQL schema: `appointments(id PK, patient_id, doctor_id, start_ts, end_ts, status, twilio_room_sid)`.  
- Migration scripts via **knex**; initial data seed for 5 test hospitals.  
- Unit tests: **jest** 27, 85 % coverage on service layer.  

### Sprint 3 (Weeks 5‑6) – React Front‑end & Routing  
- Scaffolded Next.js app (React 18, TypeScript 4.5).  
- Implemented **react-router** v6 navigation: `/login`, `/dashboard`, `/visit/:roomId`.  
- Created `VideoRoom` component wrapping Twilio Video’s `Room` object; lazy‑loaded with `React.Suspense`.  
- State management via **React Context** + `useReducer` for auth/session token.  
- UI library: **Chakra UI** for accessible components (ARIA roles, focus management).  

### Sprint 4 (Weeks 7‑8) – HIPAA Compliance Hardening  
- Added **audit_log** table; middleware logs every API call with user ID, endpoint, and timestamp.  
- Enabled **row‑level security** in PostgreSQL; policies restrict doctors to their patients only.  
- Implemented **data‑at‑rest encryption** using `pgcrypto` (`pgp_sym_encrypt`).  
- Conducted threat model review; mitigated OWASP Top 10 risks (XSS, CSRF, Injection).  

### Sprint 5 (Weeks 9‑10) – End‑to‑End Testing & CI/CD  
- Wrote Playwright tests (v1.30) covering login flow, appointment creation, and video join/leave.  
- CI pipeline on **GitHub Actions**: lint → unit tests → Playwright → Docker build.  
- Docker images: `frontend:1.0.0` (node:16‑alpine) and `backend:1.0.0` (node:16‑alpine).  
- Deployed to **AWS ECS Fargate**; traffic routed through **Application Load Balancer** with ACM‑managed TLS cert.  

### Sprint 6 (Weeks 11‑12) – Performance & Scaling  
- Load‑tested `/api/session-token` with **k6**: 2 k requests/s, 95 th percentile latency 120 ms.  
- Configured PostgreSQL connection pool (max 30) via **pg-pool**; observed <5 ms query latency for appointment reads.  
- Set Twilio Video rooms to `maxParticipants: 2`; enforced via server‑side validation.  

### Sprint 7 (Weeks 13‑14) – UX Polish & Accessibility  
- Integrated **react‑aria** for screen‑reader friendly video controls.  
- Added fallback UI for network interruptions (reconnect logic with exponential back‑off).  
- Implemented patient satisfaction survey post‑visit; stored results in `surveys` table.  

### Sprint 8 (Weeks 15‑16) – Release & Metrics  
- Production rollout: zero‑downtime deployment using blue/green strategy.  
- First‑quarter metrics (Q1 2022):  
  - **5,200+ video visits** processed, 99.2 % success rate.  
  - **Patient satisfaction:** 4.7 / 5 average rating (n = 3,842).  
  - Average session start latency: **1.8 s** from token request to video stream.  
- Post‑mortem: identified minor memory leak in Twilio SDK; patched by upgrading to `twilio-video@2.19.0`.  

---  

**Key Takeaways**  
- Tight coupling of token service and Twilio grants ensured secure, time‑bounded access.  
- Docker‑based dev parity reduced “works on my machine” bugs; CI pipeline caught regressions early.  
- Playwright end‑to‑end suite proved essential for validating real‑time video flows under varied network conditions.  

*All work delivered within the 16‑week contract, meeting the client’s HIPAA compliance checklist and performance targets.*
