# Property Listings Portal – Phase 2 (Booking Engine) (2022, Real Estate)

## Context
The client, a mid‑size real‑estate agency, already operated a Django‑powered property listings portal that showcased thousands of residential and commercial listings. Their sales team spent a significant amount of time fielding phone calls and emails from prospects who wanted to schedule on‑site viewings. The agency wanted to modernise the user experience by allowing visitors to book viewings directly from each property page, thereby increasing conversion rates and reducing manual coordination effort.

## Challenge
- **User‑facing booking flow**: Integrate a seamless, mobile‑responsive booking UI into the existing React front‑end without disrupting the current listing pages.  
- **Backend reliability**: Expose booking‑related endpoints via a REST API that could handle concurrent requests during peak listing releases.  
- **Notification reliability**: Ensure agents received instant email confirmations and that prospects received booking receipts, all while staying within the agency’s existing SendGrid budget.  
- **Data integrity**: Store booking data in the same PostgreSQL instance used for listings, enforcing constraints (e.g., no double‑booking of the same time slot).  
- **Timebox**: Deliver the full feature set within an 8‑week sprint.

## Approach
1. **API design** – Defined three primary resources in Django REST Framework: `Booking`, `TimeSlot`, and `Agent`. Leveraged `ModelViewSet` with custom actions (`/book/`, `/cancel/`) to keep the API surface minimal.  
2. **Database schema** – Added a `bookings` table with a unique composite index on `(property_id, timeslot_id)` to prevent double‑booking. Used `psycopg2` for raw queries where bulk inserts were required (e.g., bulk‑cancelling a day’s slots).  
3. **Front‑end component** – Built a reusable **BookingModal** React component in TypeScript, using `react-router-dom` for deep‑linking (`/properties/:id/book`). Integrated `axios` with an interceptor that automatically injects the CSRF token from the Django template.  
4. **Email workflow** – Configured a Django Celery worker (Docker‑based) to send asynchronous SendGrid emails on booking creation and cancellation, reducing request latency from ~1.2 s to < 300 ms.  
5. **Testing & CI** – Added unit tests for DRF serializers (coverage ≈ 92 %) and component snapshot tests with Jest. Dockerised the entire stack, enabling the team to spin up a reproducible environment in under 2 minutes.  
6. **Rollout** – Deployed to the agency’s staging environment for two weeks of UAT, gathering feedback from five agents and ten power‑users before a production push.

## Results
- **Booking requests up 50 %** within the first month after launch, measured via the new `/bookings/` analytics endpoint.  
- **Manual admin workload reduced by ~20 hours/month**, as agents no longer needed to log every phone request; the system auto‑generated calendar invites and confirmation emails.  
- **System latency** for booking submissions dropped to an average of **280 ms** (including email queueing), well under the 500 ms SLA set by the agency.  
- **Zero double‑bookings** recorded in the first 90 days, confirming the effectiveness of the composite unique index.  

## What I Would Do Differently
1. **GraphQL layer** – While REST served the MVP well, a GraphQL endpoint could have simplified future extensions (e.g., fetching property details + available slots in a single query).  
2. **Native calendar integration** – Instead of sending static iCal attachments, integrating directly with Google Calendar API would have offered agents real‑time schedule syncing.  
3. **Feature flagging** – Introducing a feature‑flag service (e.g., LaunchDarkly) early would have allowed A/B testing of the booking modal without a full deployment.  
4. **Performance profiling** – A deeper profiling run on the Celery worker pool could have uncovered a minor memory leak that surfaced after three months of heavy usage.  

Overall, Phase 2 delivered a robust, user‑centric booking engine that aligned with the agency’s growth targets while laying a solid foundation for future enhancements.
