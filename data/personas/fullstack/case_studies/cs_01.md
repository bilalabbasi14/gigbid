# Marketplace MVP for Sustainable Goods (2020 – E‑commerce)

## Context
In early 2020 a climate‑focused startup wanted to validate demand for a curated B2C marketplace of eco‑friendly products. With limited runway they needed a **minimum viable product** that could be shipped quickly, scale reliably, and support a smooth checkout experience. As the lead full‑stack engineer, I was responsible for turning the founders’ vision into a production‑ready web app within a 12‑week timeline.

## Challenge
* **Speed to market** – the team required a live storefront in under three months to secure seed funding.  
* **Complex checkout** – the marketplace had to handle multiple sellers, tax calculations, and secure payments via Stripe while staying PCI‑compliant.  
* **Scalable architecture** – anticipate rapid user growth (the founders projected >10k users in the first half‑year) without over‑engineering the stack.  
* **Maintainable codebase** – the startup would later expand the product line, so the solution needed clear separation between UI and API layers.

## Approach
1. **Server‑rendered UI** – Chose **Next.js** with **React** and **TypeScript** for fast initial page loads and SEO‑friendly product pages. Implemented authentication with **next‑auth** (email + OAuth) to keep the session logic simple.  
2. **API layer** – Built a **Node.js/Express** service exposing REST endpoints for product catalog, order management, and user profiles. Leveraged **Prisma** as the ORM to interact with a **PostgreSQL** database, enabling type‑safe queries and rapid schema migrations.  
3. **Payments** – Integrated **stripe-node** directly in the API, creating a custom checkout flow that supports one‑time purchases and future‑order saving. Utilized Stripe’s webhooks for order status updates.  
4. **Styling & UI** – Adopted **Tailwind CSS** for a utility‑first design system, allowing rapid component creation while keeping bundle size low.  
5. **Data fetching** – Used **react‑query** on the client to cache product listings and handle background refetching, reducing API load.  
6. **Containerization & Deployment** – Defined **Docker** images for both frontend and backend, orchestrated with **docker‑compose** locally. Deployed to **AWS ECS** with an Application Load Balancer, enabling zero‑downtime releases.  
7. **Testing & CI** – Set up Jest for unit tests and GitHub Actions to run linting, tests, and Docker builds on every push.

## Results
* **Launch** – MVP released in exactly **12 weeks** (mid‑June 2020).  
* **Revenue** – Generated **$45 K** in the first month, surpassing the founders’ $30 K target.  
* **User adoption** – **10,000+** registered users within six months, with a 3.2% conversion rate on the first checkout.  
* **Performance** – Average Time‑to‑First‑Byte (TTFB) of 210 ms and Lighthouse performance score of 92 on desktop.  
* **Operational stability** – Zero critical incidents during the first quarter post‑launch; Docker‑based deployments reduced rollback time to under 5 minutes.

## What I Would Do Differently
If I were to revisit the project today, I would:

1. **Adopt GraphQL** – Replace the REST endpoints with **Apollo Server** to give the frontend more flexibility in fetching nested data (e.g., seller ratings alongside products) and reduce over‑fetching.  
2. **Introduce Serverless Functions** – Move the Stripe webhook handling to AWS Lambda for better scaling under bursty traffic, while keeping the core API on ECS for consistency.  
3. **Implement Feature Flags** – Use a service like LaunchDarkly to toggle experimental UI components (e.g., product recommendation carousel) without redeploying, facilitating A/B testing.  
4. **Add Observability** – Integrate OpenTelemetry with Datadog for end‑to‑end tracing, which would make diagnosing latency spikes easier as traffic grows beyond the initial 10k users.  

Overall, the project delivered a robust, fast‑to‑market marketplace that validated the startup’s business hypothesis and laid a solid technical foundation for future growth.
