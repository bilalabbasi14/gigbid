# Content Publishing Engine — 2025 | Media Agency  

## Context  
The client, a fast‑growing media agency, needed a modern headless content management system to power a suite of digital products: two web portals, three native mobile apps, and several partner microsites. Their existing monolithic CMS required manual uploads and generated HTML on the server, leading to long publishing cycles and limited reuse of content across channels. The agency wanted a single source of truth for articles, images, and metadata, with a RESTful API that could be consumed by React‑based front‑ends and native mobile SDKs.

## Challenge  
* **Speed of publishing** – Journalists and editors were spending up to 8 hours per article to format, upload, and verify content across platforms.  
* **Multi‑channel delivery** – The solution had to serve both web (React/Next.js) and mobile (iOS/Android) clients with low latency.  
* **Scalability** – Anticipated traffic spikes during breaking news events required a robust PostgreSQL backend and containerized deployment for horizontal scaling.  
* **Team bandwidth** – The agency’s internal dev team was small; they needed a solution that could be delivered within a tight 10‑week window.

## Approach  
As Lead Engineer, I scoped the project to a **headless architecture** built on **Django** with **Django REST Framework (DRF)** for API delivery, and **Django‑CMS** for editorial workflow. The front‑end was a **React** single‑page application written in **TypeScript**, using **react‑markdown** to render markdown‑formatted articles.  

1. **API design** – Defined a set of REST endpoints (`/api/articles/`, `/api/categories/`, `/api/media/`) with pagination, filtering, and JWT authentication.  
2. **Content model** – Leveraged `django-cms` plugins to store article body as markdown, enabling editors to write in a familiar WYSIWYG interface while preserving raw markdown for the front‑end.  
3. **Dockerization** – Containerized the Django app, PostgreSQL, and a separate Nginx reverse‑proxy. Used Docker Compose for local development and Kubernetes manifests for production scaling.  
4. **CI/CD** – Set up GitHub Actions to lint TypeScript (`eslint`), run unit tests (`pytest` + `coverage`), build Docker images, and deploy to the client’s AWS Elastic Kubernetes Service (EKS) cluster.  
5. **Performance** – Added `psycopg2` connection pooling and enabled Django’s cache framework with Redis to serve frequent article reads under 120 ms.  

## Stack

## Results  
* **Publishing efficiency** – Average time to publish an article dropped from 8 hours to **3.2 hours**, a **60 % reduction** thanks to markdown authoring and instant API propagation.  
* **Channel coverage** – The same API now feeds **3 mobile apps** (React Native) and **2 web properties** (Next.js and a legacy site) without code changes.  
* **Scalability** – During a major news event the system handled **12,000 RPS** with 99.96 % uptime; auto‑scaled pods added 4 replicas within 30 seconds.  
* **Developer velocity** – The agency’s internal team can now add new content types by extending Django models and DRF serializers, cutting feature lead time from weeks to days.  

The codebase (public repo `media-publishing-engine`) includes over **12,000 lines of Python**, **4,800 lines of TypeScript**, and a full Docker‑Compose setup for local development.

## What I Would Do Differently  
1. **GraphQL layer** – Introducing **GraphQL** (via `graphene‑django`) would let front‑ends request exactly the fields they need, reducing payload size for mobile clients.  
2. **Static site generation** – For the two high‑traffic web portals, leveraging **Next.js** static generation could further improve SEO and load times, especially for evergreen articles.  
3. **Content preview** – Implement a real‑time preview environment using **WebSockets** so editors can see markdown rendering instantly, eliminating the final “publish‑preview” step.  
4. **Feature flags** – Adding a lightweight feature‑flag service (e.g., `unleash-client`) would allow the agency to roll out experimental content layouts to a subset of users without redeploying.  

Overall, the project delivered a robust, future‑proof publishing engine within the 10‑week timeline, positioning the agency to scale its digital presence across any new channel.
