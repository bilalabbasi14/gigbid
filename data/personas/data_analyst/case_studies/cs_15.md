# Engineering Log: Customer Support Ticket Classification & SLA Monitoring (SaaS, 2026)

## Project Overview
*   **Client:** SaaS Startup (Series A)
*   **Duration:** 4 Weeks (Jan 2026 – Feb 2026)
*   **Role:** Support Data Analyst
*   **Objective:** Automate ticket prioritization and visualize SLA compliance to reduce resolution times.

## Technical Stack
*   **Data Source:** Zendesk API export to BigQuery (daily incremental loads).
*   **Processing:** Python 3.10, `pandas`, `scikit-learn`.
*   **Storage:** Google Cloud BigQuery.
*   **Visualization:** Power BI Desktop connected via native BigQuery connector.

## Key Decisions & Implementation Notes

### Week 1: Data Ingestion & Cleaning
*   **Commit `a1b2c3d`:** Initial ETL pipeline setup.
    *   Ingested 14 months of historical ticket data (~45k records) into BigQuery.
    *   Schema: `support.tickets_raw` (partitioned by `created_at`).
    *   Issue: 12% of records had missing `priority` field due to legacy API changes.
    *   Fix: Implemented imputation logic in `pandas` using agent-assigned priority from `notes` field. If null, defaulted to 'Medium' based on historical distribution.
*   **Commit `e4f5g6h`:** Text preprocessing.
    *   Removed HTML tags, special characters, and stop words from `subject` and `description`.
    *   Tokenization: Used `nltk` for stemming.
    *   Data quality check: Identified 0.5% duplicate UUIDs; deduplicated based on earliest `created_at`.

### Week 2: Model Development
*   **Commit `i7j8k9l`:** Feature engineering.
    *   Created TF-IDF vectors for text classification.
    *   Added metadata features: `customer_tier` (Enterprise/Standard), `first_response_time`, `agent_id`.
*   **Commit `m0n1o2p`:** Model selection & training.
    *   Tested `Logistic Regression`, `Random Forest`, and `Multinomial Naive Bayes`.
    *   **Decision:** Selected `Multinomial Naive Bayes` for binary classification (Urgent vs. Non-Urgent).
    *   **Rationale:** Faster inference time (<5ms) and comparable accuracy to LR (94% vs 93.5%) on validation set (n=9,000).
    *   **Metrics:**
        *   Precision: 0.91
        *   Recall: 0.88
        *   F1-Score: 0.89
    *   Topic classification (5 classes: Bug, Feature Request, Billing, How-To, Account) achieved 85% accuracy using `Random Forest`.
*   **Commit `q3r4s5t`:** Model deployment.
    *   Saved model artifacts to GCS bucket `support-ml-artifacts`.
    *   Created BigQuery ML function `ML.PREDICT` to run inference on new tickets daily.

### Week 3: SLA Monitoring & Dashboard
*   **Commit `u6v7w8x`:** SLA logic definition.
    *   SLA Definition: First response < 4 hours for Enterprise, < 8 hours for Standard.
    *   Created BigQuery view `support.sla_compliance` calculating `is_breach` boolean.
    *   Identified root cause of breaches: 70% occurred during weekend hours when agent coverage was low.
*   **Commit `y9z0a1b`:** Power BI Dashboard build.
    *   **Page 1: SLA Overview.**
        *   KPI Cards: Real-time SLA Compliance Rate (Target: 95%), Avg Resolution Time.
        *   Line Chart: Daily breach rate trend (7-day moving average).
    *   **Page 2: Root Cause Analysis.**
        *   Matrix: Topic vs. Agent Team, colored by avg resolution time.
        *   Insight: 'Billing' tickets had 20% higher resolution time vs. 'How-To'.
    *   **Page 3: Priority Queue.**
        *   Table: Top 20 open tickets predicted as 'Urgent' by ML model.
        *   Added drill-through to individual ticket details.

### Week 4: Validation & Handover
*   **Commit `c2d3e4f`:** Performance validation.
    *   A/B test: Compared ML-prioritized queue vs. manual triage over 5 days.
    *   **Result:** ML queue reduced average time-to-first-response for urgent tickets by 22%.
    *   Overall average ticket resolution time reduced by 15% after 2 weeks of usage.
    *   Final SLA compliance rate: 98.2% (vs. 91% pre-implementation).
*   **Commit `g5h6i7j`:** Documentation.
    *   Documented model retraining schedule (monthly).
    *   Created Power BI DAX measure definitions for stakeholder reference.
    *   Delivered training session to support leads on dashboard interpretation.

## Challenges & Resolutions
*   **Challenge:** High false-positive rate for 'Urgent' classification in initial model (15%).
    *   **Resolution:** Adjusted classification threshold from 0.5 to 0.65. Reduced false positives to 8% while maintaining 85% recall.
*   **Challenge:** Power BI performance lag with >100k rows in matrix visual.
    *   **Resolution:** Created aggregated BigQuery view for dashboard, limited to last 90 days. Used power query refresh automation.

## Outcomes
*   **Reduced average ticket resolution time by 15%** (from 3.2 days to 2.7 days).
*   **Achieved 98% SLA compliance rate** (up from 91%).
*   Automated prioritization freed up 5 hours/week of senior agent time for complex issues.
