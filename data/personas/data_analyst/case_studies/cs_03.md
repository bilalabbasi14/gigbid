# Engineering Log: Enterprise Data Warehouse Migration & dbt Governance (2025, SaaS)

**Role:** Data Engineering Lead
**Stack:** dbt-core, Apache Airflow, BigQuery, Python, pytest-dbt
**Duration:** 12 Weeks

## Week 1-2: Audit & Baseline
- **Audit Scope:** Reviewed 47 legacy SQL scripts in BigQuery. Identified 12 critical circular dependencies and 8 undocumented CTEs causing row duplication.
- **Performance Baseline:** Measured average execution time for top 20 high-load queries: 14.2 seconds. Worst case: 45 seconds.
- **Decision:** Abandoned in-place optimization. Full migration to dbt-project structure required to enforce `dbt_project.yml` standards.
- **Action:** Created `enterprise-dbt-migration-airflow` repo. Set up local dbt 1.7 environment with `postgres` dev profile mirroring BigQuery schema.

## Week 3-5: Core Model Migration
- **Conversion:** Migrated 47 scripts to dbt models. Split monolithic `SELECT *` queries into modular `staging`, `intermediate`, and `marts` layers.
- **Optimization:** Replaced non-sargable joins with pre-aggregated intermediate tables. Reduced scan size by 60% on high-volume event logs.
- **Testing:** Implemented `dbt_utils` tests. Added 120+ schema tests (unique, not_null, relationships).
- **Issue:** `dim_customer` model failed `relationships` test due to historical orphan records in legacy data.
- **Fix:** Created `stg_customers_clean` view to filter null keys before joining. Added `dbt_expectations` for null rate < 0.1%.

## Week 6-8: Airflow Orchestration
- **Setup:** Deployed Apache Airflow 2.8 on GCP Cloud Composer.
- **Task Integration:** Created `dbt_bigquery_operator` tasks for each model layer. Configured `execution_date` logic to handle late-arriving data.
- **Dependency Graph:** Mapped 15 critical paths. Added `ExternalTaskSensor` to wait for upstream SaaS API ingestion (avg delay: 45 mins).
- **Backfill Strategy:** Implemented `backfill_date_range` utility in Python to safely rerun historical data without overwriting current partitions.
- **Config:** Set `pool` limits to 5 concurrent BigQuery queries to prevent quota exhaustion (QPS limit: 100/min).

## Week 9-10: Data Quality & Alerting
- **Alerting:** Integrated dbt `on_schema_change` hooks with Slack. Configured `dbt_cloud` webhooks to trigger `#data-alerts` channel on test failures.
- **Monitoring:** Built `pytest-dbt` suite to run in CI/CD pipeline on every PR.
- **Metric:** Added `data_quality_score` metric to track % of tests passing per model. Target: >99.5%.
- **Incident:** Detected 2% null spike in `fact_orders` during backfill. Traced to upstream API timeout.
- **Resolution:** Added retry logic (3 attempts, exponential backoff) in Airflow task. Reduced incident resolution time from ~4 hours to <30 mins by auto-alerting.

## Week 11-12: Performance Tuning & Handoff
- **Optimization:** Enabled BigQuery clustering on `event_date` and `user_id` for top 5 fact tables.
- **Result:** Average query execution time dropped from 14.2s to 8.5s (40% reduction). P95 latency improved to 12s.
- **Documentation:** Generated `dbt-docs` site. Documented 47 models, 120 tests, and 15 Airflow DAGs.
- **Training:** Conducted 3 sessions for 4 analysts on dbt best practices and Airflow UI usage.
- **Final Checklist:**
    - [ ] All models passing `dbt test --select +marts`
    - [ ] Airflow DAGs running on schedule (0 failures in 7-day trial)
    - [ ] Slack alerts verified for failure scenarios
    - [ ] Repo permissions set: Read-only for analysts, Write for DE team

## Key Takeaways
- Strict `dbt` layering prevented 90% of circular dependency issues.
- Airflow’s `ExternalTaskSensor` was crucial for handling unstable upstream API timing.
- Automated test coverage reduced manual QA effort by ~15 hours/week.
- **Next Steps:** Evaluate dbt Cloud for production hosting to reduce infra management overhead.
