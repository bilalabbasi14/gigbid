# E-commerce Conversion Funnel & Cart Abandonment Analysis | 2023 | E-Commerce

*   **Scope & Setup**: Engaged as Growth Analyst for a Series A e-commerce startup (4-week engagement). Objective: diagnose 72% cart abandonment rate and identify specific friction points in the purchase funnel.
*   **Data Architecture**: Established direct connection between Google Analytics 4 (GA4) BigQuery export and Power BI Desktop.
    *   *Note*: Initial GA4 export schema was fragmented; joined `events` table with `users` dimension to retain session-level context.
    *   *Decision*: Used `google-cloud-bigquery` Python client for initial data profiling before building Power BI datasets to validate null ratios in `item_price` and `currency` fields.
*   **SQL Development**:
    *   Wrote core SQL views in BigQuery to reconstruct the user journey: `view_product` -> `add_to_cart` -> `begin_checkout` -> `purchase`.
    *   Identified data gap: 15% of `begin_checkout` events lacked `item_id` due to a broken SDK integration on mobile web. Flagged to engineering; used `session_id` aggregation as interim workaround for analysis.
    *   Created segment definitions: `device_category` (mobile/desktop/tablet) and `traffic_source_medium` (organic/paid/social/email).
*   **Power BI Implementation**:
    *   Built "Funnel Drop-off" dashboard using drill-through capabilities.
    *   Visualized abandonment by price point: Found that items priced >$150 had a 20% higher drop-off rate at the `shipping_cost_reveal` step compared to items <$50.
    *   Added `what-if` parameters to simulate the impact of free shipping thresholds on predicted conversion rates.
*   **A/B Testing Strategy**:
    *   Collaborated with product team to design 2 A/B tests for the checkout page.
    *   *Test A*: Simplified address form (reduced fields from 8 to 4).
    *   *Test B*: Introduced express payment options (Apple Pay/Shop Pay) above the fold.
    *   *Power*: Calculated required sample size for 80% power at 95% confidence. Estimated 2 weeks per variant to reach statistical significance given daily traffic of ~12k sessions.
*   **Analysis & Insights**:
    *   *Mobile Bottleneck*: Mobile users abandoned 18% more frequently than desktop at the `payment_method` step. Root cause: Input fields for card numbers were too small for thumb input.
    *   *Price Sensitivity*: Users from paid social traffic showed higher abandonment when shipping costs exceeded 10% of cart value. Users from organic search were less sensitive.
    *   *Device Specifics*: Tablet users had the lowest completion rate (5.2%), suggesting UI scaling issues in the checkout modal.
*   **Execution & Iteration**:
    *   Week 2: Presented initial findings to CTO and Head of Growth. Stakeholders approved implementation of Express Payment buttons.
    *   Week 3: Monitored A/B test results via SQL queries on daily aggregated data.
        *   *Result*: Test B (Express Payments) showed a +9.5% lift in checkout completion.
        *   *Result*: Test A (Simplified Form) showed +4.1% lift but increased support tickets for address errors by 12%. Recommended hybrid approach: Keep simplified form but add address validation API.
*   **Final Deliverables**:
    *   Interactive Power BI report with 6 tabs: Overview, Funnel Deep Dive, Device Analysis, Traffic Source ROI, A/B Test Results, and Recommendations.
    *   SQL script repository (internal) containing all funnel logic and segment definitions for reproducibility.
    *   One-page executive summary with visualized impact of proposed changes.
*   **Outcome Verification**:
    *   Post-implementation (4 weeks after launch), cart abandonment rate dropped from 72% to 65% (-7 percentage points).
    *   Checkout completion rate increased by 12% baseline.
    *   Revenue impact: Estimated +$14,000/month in recovered sales based on average order value ($85) and traffic volume.
*   **Technical Notes**:
    *   *Performance*: Initial Power BI model took 45 seconds to load. Optimized by pre-aggregating event-level data to daily/session level in BigQuery before importing, reducing load time to <5 seconds.
    *   *Library Usage*: Leveraged `google-analytics-data` API for real-time spot checks during the A/B test period to ensure no data pipeline delays.
*   **Lessons Learned**:
    *   Always validate SDK event firing rates before starting deep funnel analysis.
    *   Mobile UX friction is often non-obvious in standard analytics; requires session recording or detailed event property analysis.
    *   A/B tests on checkout pages require careful consideration of support ticket volume as a secondary metric (quality of conversion).
